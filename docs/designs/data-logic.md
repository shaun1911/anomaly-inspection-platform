# 数据逻辑：四层、不变量、投影

> 这份文档只回答一个问题：**数据该以什么顺序被生产和消费**。
> 页面、列表、筛选、分页都是这条链末端的投影，不是业务事实。

---

## 0. 四条原则

1. **事实只写一次**：一次判定的事实来源是 `inference_job + inference_result`，其它地方只引用，不复制。
2. **上层只引用下层**：训练不直接读判例表，只读数据集快照。
3. **快照不可变**：数据集一旦冻结，成员与内容校验和固定；后续改判例不影响已冻结的快照。
4. **列表是投影**：列表 = 某一层按维度过滤后的视图。列表管理（分组/筛选/分页/保存视图）永远在最后做，且各页共用同一套口径。

---

## 1. 四层

```
L1 事实层    station · inference_job · inference_result
L2 资产层    case_item（判例）
L3 快照层    dataset · dataset_item
L4 消费层    train_job → model_version → binding → 发布 → blind_batch（验收）

投影层      工作台 / 复核队列 / 判例库 / 数据集 / 训练 / 系统
```

依赖方向只有一条：**L1 → L2 → L3 → L4**。任何反向写入都是设计缺陷。

---

## 2. 各层职责与不变量

### L1 事实层：一次判定

| 实体 | 关键字段 |
|---|---|
| `inference_job` | `code`、`part_no`、`batch_no`、`station_id`、`idempotency_key`、`status` |
| `inference_result` | `job_id`、`score`、`label`、`model_version_id`、`crop_path`、`review_status` |

不变量：

- 一个 job 最多一个 result（1:1）；
- result **必须**记录 `model_version_id`——否则"当时按哪版判的"永久丢失；
- `batch_no` 在判定时确定，事后补录必须留审计；
- 同一 `part_no` 允许多条 result（多拍/多工位），但同一站位的重复提交要用 `idempotency_key` 挡住。

### L2 资产层：判例

| 实体 | 关键字段 |
|---|---|
| `case_item` | `code`、`part_no`、`batch_no`、`verdict`、`reason`、`adjudicator`、`source`、`result_id`、`model_version_id`、`sha256`、`conflict`、`archived_at` |

不变量：

- 同一编码下 `part_no` 唯一（同件多拍只沉淀一条）；无件号时退化为 `sha256` 唯一；
- 判例必须能回答四个问题：**哪件、哪批、哪编码、按当时哪个模型版本判的**；
- 改判例留痕（审计），删除优先归档——训练集要能复现。

> 当前违反：`model_version_id` 可为空、没有 `batch_no`。这两条让判例"回答不了四问"，必须先补。

### L3 快照层：数据集

| 实体 | 关键字段 |
|---|---|
| `dataset` | `family_id`、`model_id`、`note`、`status(draft/frozen)`、`checksum`、`frozen_at` |
| `dataset_item` | `dataset_id`、`case_id`、`split(train/frozen_val)` |

不变量：

- 一个数据集只服务一个族、一个模型；
- 冻结后成员不可增删；`checksum` = 有序 `(case_id, sha256)` 的哈希，用于复现；
- 判例可以进入多个数据集（同族多模型共享），但每个数据集各自冻结、各自校验。

> 当前违反：`dataset_item` 只有 `(model_id, sha256)`，没有容器、没有版本、没有冻结时间。训练任务不引用数据集，**训练不可复现**。

### L4 消费层：训练与发布

`train_job(dataset_id)` → `model_version`（候选）→ 人工发布（`assist`）→ `binding` → `blind_batch` 验收。

不变量：

- 每个 `train_job` 必须带 `dataset_id`，否则无法回答"这版模型用了哪些数据"；
- 版本状态机单向：`candidate → shadow → assist → disabled`，回滚是一次原子交换；
- 盲判批次只能通过数据集/结果快照选取，**判例不足时不允许用未裁决结果凑数**。

---

## 3. 页面是投影

| 页面 | 读哪层 | 允许写哪层 |
|---|---|---|
| 工位面板 | L1 | L1（提交判定） |
| 复核队列 | L1 + L2 | L1（确认/暂缓）、L2（转判例） |
| 判例库 | L2 | L2（改判/归档） |
| 数据集 | L3 | L3（建快照、冻结） |
| 训练与发布 | L4 | L4 |
| 工作台 | 跨层聚合 | 不写 |

**列表规则**（所有页面一致，最后实现）：

1. 先定分组维度（族 / 编码 / 批次 / 模型版本 / 状态），再谈筛选；
2. 再定排序口径（默认最旧优先，防饿死）；
3. 最后才是分页与保存视图；
4. 总数与当前页必须同时可见——"显示 50 条"不等于"共 380 条"。

---

## 4. 当前缺口与修复顺序

| 顺序 | 缺口 | 为什么排这个位置 |
|---|---|---|
| 1 | **批次**贯通：`batch_no` 进 job → result → case，可筛可追溯 | 事实层缺失，上层全部受影响 |
| 2 | **模型版本**必填：`source=result` 的判例必须带 `model_version_id` | 资产层可复现的前提 |
| 3 | **数据集容器**：`dataset` + 重建 `dataset_item` + 冻结 + 校验和 | 训练可复现的前提 |
| 4 | **训练引用数据集**：`train_job.dataset_id` | 消费层闭环 |
| 5 | **列表投影**：判例库/数据集/队列统一分组、筛选、分页、保存视图 | 最后做，前面不稳定时做了也要返工 |

分页排在第 5 位，不是因为它不重要，而是**它必须建立在前面四层稳定的分组维度上**。

---

## 5. 验收这条逻辑是否成立

用三个问题自检：

1. 给定一个件号，能否还原：哪批、哪编码、当时哪版模型、谁复核、进了哪个数据集？→ 做不到说明 L1/L2 断链。
2. 给定一版模型，能否还原训练用的数据集快照与校验和？→ 做不到说明 L3 缺失。
3. 给定一个数据集，能否列出它引用了哪些判例、其中多少条后来被改判？→ 做不到说明审计与快照关系没建。
